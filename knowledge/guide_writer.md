# 📚 기초 가이드 작가 교본 (3D 강사)

## 독자
툴을 막 배우는 학생부터, 다른 툴에서 넘어온 실무자까지. 영상과 함께 보며 **바로 따라 할 수 있어야** 한다.

## 구성 원칙
- 요약: "무엇을 하는 기능인가" 1~2문장. 비유 하나 허용("철사를 구부리듯").
- 이럴 때 씁니다: 실제 작업 상황 3개 (예: 파이프, 휘어진 간판, 나뭇잎).
- 따라 하기 4~7단계: **메뉴 경로와 단축키를 정확히**. 각 단계는 한 동작.
  - 3ds Max: Command Panel → Modify 탭 → Modifier List 에서 선택. 서브오브젝트는 1~5 키.
  - Blender: Properties → Modifier(렌치) 탭 → Add Modifier → 분류(Generate/Deform…). Tab 으로 Edit Mode.
  - Houdini: 네트워크 뷰에서 Tab → 노드 이름 검색. 파라미터 창에서 조정.
  - Unreal: Content Browser / Details 패널 / Project Settings 경로를 정확히.
- 주요 옵션: UI 에 보이는 **영문 이름 그대로** + 한국어 효과 한 줄. 값의 "감"을 주면 좋다(예: Segments 는 휘는 축 방향으로 충분히).
- 활용 예시 2~3개: 결과물이 상상되는 구체적 상황 + 2~4단계.
- 자주 하는 실수 2~3개: "실수 → 해결" 형식 (FAQ 로도 쓰임). 초보가 실제로 막히는 지점:
  세그먼트 부족, Gizmo/Pivot 위치, 스택 순서, 스케일 미적용(Blender Apply Scale), 법선 뒤집힘, 서브디비전 레벨 과다.

## 정확성
- 버전마다 다른 것은 "최신 버전 기준" 또는 생략. 존재가 확실하지 않은 옵션은 쓰지 않는다.
- 공식 문서 본문이 주어지면 그것을 정답으로.

## 그림·영상과 함께 읽히게 (사장님 방향: 글보다 그림)
- 단계마다 **화면에서 무엇이 보이는지** 한 구절: "Modifier List 를 열면 OBJECT-SPACE MODIFIERS 목록이 보입니다".
- 결과 확인 방법을 마지막 단계에: "뷰포트에서 모서리가 둥글게 바뀌면 성공".
- 영상이 붙으므로 영상과 다른 말을 하지 않는다. 확실하지 않은 값·버전은 빼고 "공식 문서 기준"으로.

## 도구별 화면 규칙 (추가)
- Pixyz Studio: 메뉴 바(File·Scene·CAD·Mesh·Optimize Mesh·UVs) → 대화 상자에서 값 → Execute. 왼쪽 Product Structure(트리)에서
  고르고, 오른쪽 Inspector 에서 속성 확인. 함수 이름은 영문 그대로(Decimate To Target, Repair Mesh, Generate LOD Chain).
- NVIDIA Omniverse: 런처 지원 종료(2025) 이후 Kit 앱 기준. Stage 패널(USD 계층)·Property 패널.

## 심화 매뉴얼 (/manual/)
- 기초 가이드를 반복하지 말고 **옵션 전체**: 값 범위·기본값(문서에 있을 때만)·효과·실무 팁.
- 응용 레시피는 다른 기능과 조합해 실제 결과물이 나오는 순서. "무거울 때"는 구체적 원인→대처.
- Blender 는 옵션 값 비교 그림이 자동으로 렌더되므로, 렌더에서 **눈에 보이는 옵션**의 효과를 분명히 쓴다.

## 툴 비교 (/compare/)
- 같은 작업을 툴마다 정확한 메뉴·모디파이어·노드 이름으로. 기본 기능이 없으면 "없음"이라고 쓰고 유명 플러그인만.
- 상황별 추천은 "누가·언제·왜" 한 줄. 툴 사이로 넘길 때(축·스케일·단위·이름 규칙)는 실무에서 가장 많이 틀리는 것부터.

## 오류 해결 (/fix/)
- 제목은 오류 메시지 원문 그대로(검색어). 원인은 가능성 높은 순, 해결 순서는 쉬운 것부터, 확인 방법과 재발 방지까지.
