툴셋과 툴 레지스트리의 구조

AI 에이전트가 프로젝트에서 수행하는 모든 작업은 툴셋에서 시작됩니다. 툴셋과 툴 레지스트리가 상호작용하여 에이전트가 필요한 기능을 호출할 수 있도록 준비합니다.

툴 검색과 디스커버리 도구 제한

수백 개의 기능이 존재할 때 툴 검색 기능은 에이전트에게 전체 목록 대신 단 3개의 디스커버리 도구만 노출합니다. 이 방식을 통해 에이전트가 혼란 없이 필요한 기능을 정확히 찾도록 유도합니다.

ModelContextProtocol.RefreshTools 활용 시점

새로운 도구를 추가하거나 설정을 변경한 뒤에는 ModelContextProtocol.RefreshTools를 실행해야 합니다. 이 과정은 레지스트리를 갱신하여 에이전트가 최신 도구 목록을 인식하게 만듭니다.

Python과 C++을 이용한 커스텀 도구 제작

작업 스타일에 맞추어 Python이나 C++로 자신만의 커스텀 툴셋을 구축할 수 있습니다. 프로젝트 환경에 맞춰 필요한 명령과 에이전트 연동 방식을 직접 확장하는 구조입니다.

💡 에디터 코멘트

ModelContextProtocol.RefreshTools 명령어를 활용하면 수백 개의 도구 중 3개의 디스커버리 도구만 에이전트에 노출하여 탐색 효율을 유지할 수 있습니다. 자체 제작 시 Python과 C++ 환경에서 도구 레지스트리를 확장하는 방식을 적용합니다.

❓ 자주 묻는 질문

Q. 에이전트가 수백 개의 도구 대신 3개만 보는 이유는 무엇인가요?
A. 툴 검색 기능이 에이전트에게 방대한 목록 대신 3개의 디스커버리 도구만 먼저 노출하여 효율적인 탐색을 돕기 때문입니다.

Q. ModelContextProtocol.RefreshTools는 언제 실행해야 하나요?
A. 새로운 커스텀 도구를 만들거나 툴 레지스트리에 변경 사항이 생겼을 때 실행하여 에이전트의 도구 목록을 갱신합니다.

Q. 커스텀 툴셋은 어떤 언어로 만들 수 있나요?
A. 작업 환경에 따라 Python 또는 C++를 사용하여 직접 구축할 수 있습니다.
