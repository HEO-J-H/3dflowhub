한 줄 요약 — Unity로 개발된 영구 지속형 MMO 샌드박스 게임 SEED가 플레이어가 직접 구축하는 방대한 월드 데이터를 URP와 BatchRendererGroup으로 렌더링하는 최적화 사례를 공개했습니다.

분류: Game Engine › Unity › 작품·제작 사례

서버 권위형 아키텍처와 Unity 클라이언트

클강 게임즈의 SEED는 플레이어가 로그아웃해도 월드가 계속 작동하는 영구 지속형 MMO 샌드박스입니다. 서버에서 시뮬레이션을 처리하고 Unity 클라이언트는 스트리밍되는 상태를 읽어 렌더링을 담당합니다.

정점 데이터 기반 로우폴리 스타일과 모듈형 구조

텍스처 대신 정점 데이터에 색상과 재질 정의를 베이킹하여 모바일 환경의 Shading 부하를 줄였습니다. 건물을 통째로 올리지 않고 1미터 Grid 기준의 벽, 바닥, 지붕 등의 작은 모듈 조합으로 생성합니다.

BatchRendererGroup과 C# Job System의 결합

19만 개가 넘는 모듈을 렌더링하기 위해 BatchRendererGroup을 활용하여 배치 처리를 수행합니다. 이 작업들은 C# Job System 위에서 실행되며 Burst 컴파일러로 컴파일되어 성능을 유지합니다.

URP 기본 경로를 활용한 멀티플랫폼 확장

PC와 모바일 양쪽을 지원하기 위해 Unity의 Universal Render Pipeline 기본 설정을 최대한 유지합니다. Unity 업데이트 주기에 맞춰 엔진 버전을 업그레이드하면서 커스텀 렌더러 기능으로 필요한 효과만 확장합니다.

💡 에디터 코멘트

Unity 6.3 환경에서 기본 URP 구조를 유지하면서 커스텀 렌더러와 C# Job System, Burst 컴파일러를 조합해 수십만 개의 모듈을 끊김 없이 처리합니다.

Q. SEED는 어떤 엔진으로 개발되었나요?
A. Unity 엔진으로 개발되었으며 현재 Unity 6.3 버전을 사용하고 있습니다.

A. BatchRendererGroup과 C# Job System, Burst 컴파일러를 조합해 대량의 작은 모듈을 효율적으로 묶어서 처리합니다.
