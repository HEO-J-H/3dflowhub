한 줄 요약 — NVIDIA KGMON 팀이 KDD Cup 2026 Data Agents 경진대회에서 소형 LLM과 제약된 하네스를 활용해 신뢰할 수 있는 데이터 분석 에이전트를 구축한 핵심 노하우를 공유합니다.

분류: AI 3D › AI 도구

KDD Cup Data Agents 경진대회와 NVIDIA KGMON 팀의 성과

NVIDIA KGMON 팀은 KDD Cup 2026 Data Agents 대회에서 2위를 차지하며 소형의 고정된 LLM을 감싸는 제약된 하네스 설계의 우수성을 입증했습니다. 대회는 데이터베이스, CSV, JSON, 문서, 비디오 등 이종 데이터 소스에 걸친 자연어 질문에 답하는 에이전트를 요구했습니다. 팀은 모델 자체의 자유도를 높이는 대신 전처리와 제한된 도구 세트를 통해 소형 오픈 모델의 한계를 극복했습니다.

정형 데이터를 단일 SQLite 쿼리 인터페이스로 통합하기

다양한 형식의 데이터 소스를 처리하기 위해 KGMON은 CSV와 JSON 파일을 기존 SQLite 데이터베이스의 테이블로 변환했습니다. 이를 통해 에이전트가 단일 SQL 인터페이스를 통해 모든 정형 데이터에 접근하도록 만들어 라우팅 오류를 줄였습니다. 사전 스키마 정찰 단계를 통해 에이전트에게 테이블, 조인 키, 데이터 품질 문제를 미리 브리핑하여 본 추론 루프의 정확도를 높였습니다.

에이전트의 액션 스페이스 제한과 미들웨어의 역할

에이전트의 오작동을 막기 위해 도구 세트를 schema(), sql(query), write_answer(df), prose_helper() 등으로 엄격하게 제한했습니다. 미들웨어는 에이전트의 잘못된 도구 호출을 실시간으로 수정하며, 지속형 상태 관리 기능은 중간 결과물을 유지했습니다. 이러한 구조는 에이전트가 길을 잃거나 불필요한 시행착오에 빠지는 것을 방지합니다.

문서 검사 분리와 실행 추적을 통한 지속적인 개선

비정형 문서 검사는 타겟형 미리보기와 정규식 검색을 활용하여 별도의 제로 템퍼러리 LLM 호출을 거치는 prose_helper 도구로 분리했습니다. 이를 통해 원시 텍스트가 메인 컨텍스트를 오염시키는 것을 막고 핵심 답변 추출에 집중할 수 있었습니다. 프롬프트와 도구 호출, 중간 결과가 담긴 실행 추적 로그는 전문 검사 에이전트가 실패 원인을 분류하고 하네스를 개선하는 기초 자료로 활용되었습니다.

💡 에디터 코멘트

이 글은 복잡한 데이터 분석 에이전트를 구축할 때 무조건 거대 모델을 쓰는 것보다 엄격한 도구 제약과 사전 스키마 정리가 얼마나 중요한지 잘 보여줍니다. 3D·VFX 파이프라인이나 게임 데이터 자동화에서 LLM 에이전트를 도입할 때, 에이전트의 자유도를 줄이고 정형화된 하네스를 감싸는 방식이 오류를 획기적으로 줄이는 실무적 해법이 될 수 있습니다. 특히 한정된 자원(GPU 및 소형 오픈소스 모델) 환경에서 안정적인 자동화 툴을 설계하려는 개발자와 테크니컬 디렉터에게 큰 시사점을 줍니다.
