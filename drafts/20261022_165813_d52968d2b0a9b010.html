NVIDIA KvikIO와 cuFile의 역할

NVIDIA KvikIO는 cuFile C API 상위에 위치하여 고성능 파일 I/O를 위한 직관적인 Python 및 C++ 인터페이스를 제공합니다. KvikIO와 cuFile은 각각 독립적으로 경로 선택 결정을 내리며, KvikIO는 cuFile 호출 여부를 결정하고 cuFile은 가속화된 nvidia-fs 커널 모듈이나 CPU 경유 호환 경로를 사용할지 판단합니다. 이를 통해 애플리케이션 계층에서 효율적인 스토리지 I/O 제어가 가능해집니다.

GPUDirect Storage(GDS)를 통한 직접 데이터 경로

NVIDIA Magnum IO GPUDirect Storage는 지원되는 스토리지와 GPU 메모리 간의 직접적인 데이터 경로를 제공하여 불필요한 CPU 메모리 스테이징을 방지합니다. 이는 시스템 전체의 CPU 사용률을 낮추고 폭발적으로 증가하는 데이터 세트 처리 요구를 충족합니다. 다양한 주요 스토리지 공급업체가 이 에코시스템을 지원하고 있어 대규모 데이터 집약적 워크로드에 필수적입니다.

런타임 설정과 환경 변수 제어

KvikIO의 동작은 KVIKIO_COMPAT_MODE 및 KVIKIO_GDS_THRESHOLD와 같은 런타임 설정으로 제어할 수 있습니다. 또한 cufile.json의 execution.parallel_io 및 execution.min_io_threshold_size_kb 설정을 통해 cuFile이 요청을 분해하고 예약하는 방식을 조절합니다. 이러한 파라미터를 워크로드 특성에 맞게 구성하여 최적의 I/O 성능을 이끌어낼 수 있습니다.

GDS 가속 경로 활성화 확인 및 통계 분석

CUFILE_STATS_LEVEL=3 환경 변수를 설정하고 gds_stats를 통해 프로세스별 cuFile 통계를 수집할 수 있습니다. 이를 통해 작업이 nvidia-fs 가속 경로(nvfs 카운터)를 거쳤는지 혹은 호환성 경로(posix 카운터)를 거쳤는지 확인할 수 있습니다. 개발자는 이 도구를 활용해 GDS 설정이 올바르게 적용되었는지 검증할 수 있습니다.

❓ 자주 묻는 질문

Q. NVIDIA KvikIO는 어떤 역할을 하나요?
A. cuFile C API 위에 구축된 Python 및 C++ 라이브러리로, GPU 메모리로의 고속 파일 I/O를 처리하기 위한 고수준 인터페이스와 제어 옵션을 제공합니다.

Q. GDS 가속 경로가 제대로 작동하는지 어떻게 확인하나요?
A. CUFILE_STATS_LEVEL=3을 설정하고 gds_stats를 검사하여 nvfs 카운터가 증가했는지 확인하면 가속 경로 활성화 여부를 알 수 있습니다.
