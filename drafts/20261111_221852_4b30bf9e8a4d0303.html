한 줄 요약 — NVIDIA AI Cluster Runtime(AICR) v1.2.0이 k8s-aibom 1.6.2와 통합되어 Kubernetes 환경에서 실행되는 AI 워크로드의 빌드 오브 마테리얼(AIBOM) 추적 기능을 제공합니다.

분류: AI 3D › NVIDIA DSX › 업데이트·출시

k8s-aibom 통합과 AIBOM 레코드 생성

NVIDIA AI Cluster Runtime(AICR)은 오픈소스 k8s-aibom 프로젝트를 기반으로 자격이 검증된 AI 빌드 오브 마테리얼 컴포넌트를 포함합니다. 이를 통해 Kubernetes에서 구동되는 AI 워크로드를 추적하며, CycloneDX 1.6 AIBOM 레코드를 신뢰도 티어 및 증거 로케이터와 함께 출력합니다. h100-gke-cos-inference 및 h100-gke-cos-inference-dynamo 두 가지 스톡 레시피가 k8s-aibom을 기본으로 선택합니다.

실행 중인 워크로드 가시성 확보

Application 팀이 플랫폼 레시피와 독립적으로 워크로드를 정의하고 업데이트하기 때문에, 재현 가능한 배포 번들만으로는 각 노드에서 어떤 아티팩트가 실행 중인지 파악하기 어렵습니다. 가변 이미지 태그 :latest와 같은 요소는 동일한 태그 아래에서 노드마다 다른 코드가 실행되게 만드는 복잡성을 더합니다. AICR과 k8s-aibom 통합은 이러한 간극을 좁혀 배포된 워크로드의 실제 상태를 명확히 가시화합니다.

레시피 구성과 런타임 인벤토리 플래그

다른 GKE 레시피의 경우 --runtime-inventory 플래그를 사용하여 k8s-aibom을 선택적으로 활성화하거나 비활성화할 수 있습니다. AICR은 검증된 GPU 플랫폼 구성을 버전이 고정된 레시피와 재현 가능한 배포 번들로 변환합니다. 번들에는 체크섬이 포함되며, aicr bundle --attest 명령을 통해 서명이 가능합니다.

자원 소비량과 네임스페이스 제어

통합 검증은 k8s-aibom 1.6.2가 핀닝된 AICR v1.2.0을 통해 이루어졌으며, 정상 상태 관찰 시 분당 약 4회의 API 서버 요청, 2.2 밀리코어의 평균 CPU 사용량을 보였습니다. Controller 메모리 워킹 셋은 28~34 MiB 수준을 유지했습니다. 네임스페이스 옵트인(opt-in) 제어 기능을 통해 어떤 네임스페이스에서 AIBOM 레코드를 출력할지 결정할 수 있으며, 모델 및 컨테이너 이미지 세부 정보가 포함된 vLLM 추론 배포 같은 워크로드 카테고리를 자동으로 분류합니다.

💡 에디터 코멘트

NVIDIA AI Cluster Runtime v1.2.0에 핀닝된 k8s-aibom 1.6.2는 정상 상태에서 분당 약 4회의 API 서버 요청과 2.2 밀리코어의 평균 CPU 사용량을 기록하여 대규모 클러스터에서도 오버헤드가 적습니다.

❓ 자주 묻는 질문

Q. NVIDIA AICR에서 k8s-aibom을 기본으로 사용하는 레시피는 무엇인가요?
A. h100-gke-cos-inference 및 h100-gke-cos-inference-dynamo 두 가지 스톡 레시피가 기본으로 선택합니다.

Q. 다른 GKE 레시피에서 런타임 인벤토리를 활성화하려면 어떻게 해야 하나요?
A. 레시피 생성 시 --runtime-inventory 플래그를 사용하여 옵트인할 수 있으며, 반대의 경우 --runtime-inventory disabled를 사용할 수 있습니다.
